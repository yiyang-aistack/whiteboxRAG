whiteBoxRAG 产品说明与常见问题（演示知识库）

一、产品定位

whiteBoxRAG 是一套轻量化、可私有化部署的检索增强生成（RAG）系统，基于 FastAPI、LlamaIndex、ChromaDB 与 Ollama 构建。它的目标是在仅有 8GB 内存的 CPU 机器上运行，不依赖 Redis、MySQL 或消息队列等中间件，向量、文档、日志、溯源记录和任务状态全部以本地文件形式存储。

二、默认参数与核心指标

1. 服务默认监听端口为 8080，健康检查地址是 /api/health。
2. 混合检索默认启用，BM25 权重为 0.4，向量权重为 0.6。
3. 向量检索默认 top_k 为 5，相似度阈值默认 0.1。
4. 检索器的重排序数量（rerank_top_k）默认是 10。
5. 文档分块大小默认 512 字符，分块重叠默认 50 字符，单个文件上传上限为 50MB。
6. 上下文压缩默认开启，压缩后最大 2048 tokens。
7. API 层共提供 58 个端点，划分为知识库管理、对话问答、场景管理、质量评估、文档优化、系统监控六个模块。
8. API 默认限流为每个 IP 每分钟 60 次请求。

三、支持的文档格式

系统支持解析 PDF、Word（.docx 与 .doc）、纯文本 TXT、Excel（.xlsx 与 .xls）以及 PowerPoint（.pptx）。上传时会同时进行扩展名校验与文件魔数（Magic Number）校验，防止把可执行文件伪装成文档。

四、白盒溯源能力

1. 系统内置句子级溯源：AI 回答会被拆分为句子，逐句与检索到的文档片段做语义对齐，并标注三种可信度——有文档依据、低置信度、无依据推断。
2. 检索溯源面板分为"业务摘要"和"技术详情"两个视图。业务摘要面向业务管理员，第一屏先给出知识库匹配结论、召回汇总与逐句可信度；技术详情面向技术人员，展示查询改写流水、BM25 与向量三路检索对比、融合计算详情和句子级相似度数值。

五、未召回诊断

当用户认为某篇文档本应被检索到却没有出现时，可以查看未召回诊断。系统会给出根因判断，例如元数据过滤把它排除、得分刚好低于阈值、只有一种检索模式命中，或者查询缺少关键词。

六、质量评估

评估框架覆盖三个层次：检索质量（平均得分、得分标准差）、答案质量（语义忠实度、语义相关性、上下文利用率）以及安全性（幻觉率、拒答准确率、空回复率）。评估结果可以汇编为可分享的报告。

七、部署方式

1. 一键启动：python main.py --install，脚本会自动检查环境、安装依赖并启动服务。
2. 容器部署：使用 deploy/Dockerfile 构建镜像，或直接执行 docker compose up 同时启动 Ollama 与应用。
3. 生产模式：使用 Gunicorn 以单 worker、多线程方式运行，例如 gunicorn --bind 0.0.0.0:8080 --workers 1 --threads 4 api.api:app。

八、常见问题

问：为什么推荐单 worker 运行？
答：向量库与 BM25 索引保存在进程内存中，多 worker 会复制这份状态并导致索引不一致。

问：没有本地 GPU 可以运行吗？
答：可以。系统面向 CPU 环境设计，通过 Ollama 运行量化后的 7B 模型（例如 qwen2.5:7b）即可满足中小规模知识库的问答需求。

问：数据会离开企业内网吗？
答：默认不会。文档解析、向量化、检索与生成全部在本地完成；只有在显式切换 LLM_PROVIDER=openai 时才会调用云端 API。
